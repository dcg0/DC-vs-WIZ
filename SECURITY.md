# Política de seguridad

## Versiones compatibles

Se da mantenimiento de seguridad a la versión publicada más reciente y a la rama `main`.

## Informar de una vulnerabilidad

No publiques credenciales, tokens, datos personales ni detalles de explotación en un issue público.

Cuando esté disponible, utiliza **Report a vulnerability** en la pestaña **Security** del repositorio para crear un aviso privado de GitHub. Si esa opción no está disponible, solicita al mantenedor un canal privado desde su perfil de GitHub antes de compartir los detalles.

Incluye, siempre que sea posible:

- el commit, versión o archivo afectado;
- pasos mínimos para reproducir el problema;
- impacto esperado y una posible mitigación;
- cualquier registro ya redactado de secretos o datos personales.

No cambies ni subas claves de firma, archivos `.env`, contraseñas o tokens como parte de una corrección. Las correcciones deben conservar la funcionalidad existente y no incluir secretos.
